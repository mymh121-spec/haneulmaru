Rust/USB-Wi-Fi 전환 검증

Windows x64에서 Rust 릴리스 실행 파일을 빌드했습니다. Rust 테스트는 두 USB 패킷 형식, 네 방향 학습 벡터, 잘못된 키, 중복·역순 패킷, USB 세션 재연결, 영상 letterbox 및 class-agnostic NMS를 확인합니다.
실제 ONNX 테스트 그래프를 Rust 작업자에서 실행해 프레임 색상에 따른 탐지 결과, 원본 좌표 복원과 빈 결과를 확인했습니다. Android 앱의 Java 컴파일, DEX 생성, 매니페스트와 APK v2/v3 서명을 확인했습니다.
실제 NU40과 S22는 이번 환경에 연결되지 않았습니다. 샌드박스에서 서로 다른 프로세스 간 UDP 루프백 수신도 확인하지 못했습니다. 실제 공유기/핫스팟 왕복과 휴대폰 USB 권한 및 재연결은 실기기 확인이 필요합니다. 실제 R/B/G 학습 모델은 저장소에 없어 정확도와 처리속도는 측정하지 않았습니다.

다중 객체 합성 영상 검증
20fps, 48프레임, 512×512 무손실 AVI를 디코딩해 PC 배포용 Rust 엔진과 Rust 추적기에 입력했습니다. 합성 점 네 개(같은 색 두 개 포함)의 위치는 프레임 픽셀에서 시험용 ONNX 모델이 탐지했습니다. 프레임별로 보여야 하는 177건의 색상과 박스 좌표 177건이 일치했고, 중복 ID와 ID 교체는 0건이었습니다. 빨강 두 객체의 교차 중 한 객체는 5프레임, 파랑 객체는 4프레임 가려지도록 했습니다. 재등장 후 각각 이전 ID를 받았습니다. 테스트 정답은 추적기 입력에 포함되지 않습니다. 실제 드론 영상에서의 탐지 정확도와 ID 유지율은 아직 측정하지 않았습니다.


데이터셋 확장 검증
동봉된 photo_color_v1의 YOLO와 COCO 주석을 각각 새 폴더로 가져왔습니다. 두 경로 모두 단일 클래스 drone, 학습 840장, 검증 240장, 시험 120장이었으며 각 분할의 박스 수도 일치했습니다.
가상 4클래스 모델로 4가지 ONNX 출력 형식의 점수·박스·클래스 ID를 검사했습니다. 겹친 두 객체의 클래스가 다를 때 두 결과가 남았고, crate와 표지판에 서로 다른 추적 ID가 유지됐습니다. 학습과 실제 모델 성능 평가는 수행하지 않았습니다.
기존 합성 AVI는 기본 설정과 한글 프로필 각각 48프레임·177건이었고, 박스 좌표와 ID는 동봉된 기준 결과와 일치했습니다. FFmpeg로 AVI를 읽어 Rust 엔진과 추적기를 실행했습니다. OpenCV 표시 창은 이번 검증에서 실행하지 않았습니다.
