하늘마루 PC Rust 영상 인식과 USB 센서 중계

기기 연결
NU40 → USB CDC → S22의 하늘마루 USB 앱 → Wi-Fi UDP 8793 → PC Rust.
앱 설치와 센서 단독 시험은 프로젝트 루트의 NU40_연동_사용법.txt를 따르세요.
이 APK는 USB 센서 중계용입니다. 실시간 영상 입력에는 별도 S22 카메라 송신기의 스트림 URL이 필요합니다. 기존 WebRTC 데모는 PC에서 렌더링한 영상을 폰으로 보내는 별도 모드입니다.

다른 객체 탐지 데이터셋을 추가하려면 DATASETS.md를 참조하세요. YOLO·COCO 가져오기, 클래스 ID 매핑, 학습 및 --profile로 모델을 교체하는 방법이 있습니다. 아래는 기존 R/B/G 모델 기준입니다.

영상 모델 준비
기존 photo_color_v1의 R/B/G 3클래스 YOLO11 학습 결과 best.pt를 사용합니다. 학습 환경에서 아래와 같이 내보내고 생성한 ONNX 파일을 multidevice_app/models/best.onnx로 복사합니다.
  yolo export model=best.pt format=onnx imgsz=640 batch=1 dynamic=False half=False nms=False opset=13
입력 images=FP32 [1,3,640,640], 출력 output0=FP32 [1,7,N], 클래스 순서는 R, B, G입니다. ONNX 파일은 가중치를 포함하는 단일 파일이어야 합니다. 실제 학습된 가중치는 배포물에 없습니다.

Windows에서 영상 인식
multidevice_app 폴더에서 다음을 실행합니다.
  py -3 -m venv .venv
  .venv\Scripts\python.exe -m pip install -r requirements.txt
  .venv\Scripts\python.exe run.py --source "S22 카메라 스트림 URL" --show
  .venv\Scripts\python.exe run.py --source "C:\videos\sample.mp4" --recording --jsonl result.jsonl
기본 설정에서 PC의 Rust 엔진이 동시에 여러 R/B/G 객체를 탐지하고 Rust 추적기가 프레임 사이의 ID를 연결합니다. 화면에 객체 수, ID, 색상, 신뢰도가 나타납니다. JSONL의 tracks 배열에는 현재 프레임에서 관측한 객체만 기록합니다. 객체의 식별자는 session_id와 id를 함께 사용하세요.

합성 영상으로 먼저 시험하기
Windows에서 다중추적_데모.cmd를 실행합니다. 처음 실행할 때 Python 3.10 이상과 패키지 다운로드 연결이 필요합니다. 준비된 환경에서는 아래 명령으로 전체 프레임의 결과를 새 파일에 저장할 수 있습니다.
  .venv\Scripts\python.exe run.py --config demo/config.json --source demo/multi-tracking.avi --recording --jsonl result.jsonl
demo/synthetic-peaks.onnx는 이 합성 장면의 색상점을 인식하는 시험용 모델입니다. demo/expected-tracks.jsonl에서 프레임별 정답과 대조한 박스와 ID를 확인할 수 있습니다. 실제 드론 영상에서는 기본 설정과 학습된 models/best.onnx를 사용합니다.

기본 추적기는 관측한 이동 속도와 박스 겹침, 크기, 색상을 비교해 한 객체에 한 ID를 할당합니다. 신뢰도 0.4 이상이면 새 ID를 발급하고, 그 미만의 관측은 기존 ID에만 연결합니다. ID가 아직 없으면 null로 표시합니다. 마지막 관측 후 최대 750ms 동안 후보를 유지합니다. 가려진 프레임에는 박스를 만들지 않습니다. 세션이 새로 시작하거나 해상도가 바뀌면 이전 ID와 구분합니다. 외형이 비슷한 객체의 장시간 가림이나 급격한 카메라 이동에서는 ID가 바뀔 수 있습니다.
--tracker none은 추적을 끕니다. 선택 가능한 ByteTrack/BoT-SORT를 쓰려면 requirements-inference.txt를 설치하고 --tracker bytetrack 또는 --tracker botsort를 사용하세요. --engine disabled로 영상/센서만 볼 수도 있습니다.

코드와 연산
OpenCV/Python은 입력 영상 디코딩과 화면 표시를 담당합니다. Rust 프로세스는 모델을 한 번 로드한 뒤 프레임마다 BGR → RGB letterbox → FP32 텐서 → ONNX Runtime CPU 추론 → 박스 좌표 복원과 NMS를 실행합니다. Rust가 Wi-Fi 센서 패킷과 학습 벡터로 방향을 판정합니다. 기본 다중 객체 추적 연산도 PC의 Rust 실행 파일이 맡습니다. 녹화 영상에는 현재 센서값이 붙지 않습니다. 라이브 영상과 센서는 PC 수신 시각 기준의 근사 연결입니다.

배포와 빌드
Windows x64 Rust 실행 파일은 bin/haneulmaru.exe입니다. 표준 Windows System32의 onnxruntime.dll을 사용합니다. 없으면 Microsoft의 ONNX Runtime CPU 라이브러리를 준비하고 HANEULMARU_ORT_LIB에 onnxruntime.dll의 절대 경로를 지정합니다. Linux에서는 libonnxruntime.so를 설치하거나 같은 환경변수에 절대 경로를 지정합니다. 추론 자체에는 Python 학습 환경이 필요하지 않습니다.
Rust 재빌드: rust 폴더에서 cargo build --release --locked. bin에 배포된 실행 파일이 있으면 새 빌드로 교체하세요.
Android 재빌드: Android Studio에서 android 폴더를 열고 SDK 35, JDK 17+, Gradle 8.11.1로 assembleDebug를 실행합니다. 기존 Kotlin 파일은 참고용이고 실제 USB 서비스는 src/main/java에 있습니다.

확인
rust 폴더에서 cargo test --locked. 저장소 루트에서 python -m unittest multidevice_app.test_rust_host multidevice_app.test_multi_tracking. 검사는 학습된 드론 모델 대신 입력에 따라 출력이 달라지는 소형 ONNX 테스트 그래프를 사용합니다. 대상 S22/NU40의 실물 연결과 실제 학습 모델 정확도는 별도 확인이 필요합니다.
