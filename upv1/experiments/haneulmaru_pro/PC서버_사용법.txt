하늘마루 PRO — PC 서버 렌더링 / 휴대폰 수신

프로젝트 루트의 하늘마루_PC서버_실행.cmd를 실행합니다.
1. PC 서버가 8792 포트에서 시작됩니다. 기존 8790/8791 프로그램은 유지됩니다.
2. 자동으로 열린 PC 서버 렌더러 탭을 화면에 열어둡니다. 최소화/배경 탭에서는 프레임이 제한될 수 있습니다.
3. PC와 폰을 같은 노트북 핫스팟 또는 기기 간 통신이 허용된 Wi-Fi에 연결합니다.
4. PC 화면의 새 QR을 폰 Chrome에서 열고 'PC 연결 시작'을 누릅니다.
5. 가상환경/카메라 AR 전환. 폰 카메라 영상은 폰에만 남고 PC로 전송하지 않습니다.
6. 폰의 터치·핀치·방향 센서·드론 수·일시정지·2D 전환을 PC에 전달합니다.

구조: PC Three.js 장면 → canvas.captureStream → WebRTC 비디오 → 휴대폰 재생.
조작/상태는 WebRTC DataChannel. Python 서버는 SDP/ICE 연결 정보만 교환합니다.
Cloudflare HTTPS는 페이지/시그널링 전달용이며 비디오 중계 서버(TURN)는 아닙니다.
같은 Wi-Fi라도 게스트/AP isolation, 방화벽, WebRTC 기기 검색 제한이면 연결이 실패할 수 있습니다.
TURN 없이 LAN 직접 연결을 우선 구현했습니다. 서로 다른 네트워크 연결은 보장하지 않습니다.
AR 합성은 PC 배경의 녹색을 휴대폰 GPU의 단순 셰이더로 제거하는 크로마키 방식입니다.
PC에서 모든 지형과 비행체를 렌더링합니다. 폰은 비디오 디코딩/카메라 합성만 수행합니다.
기존 독립 실행 앱의 WebXR 공간 AR과는 다른 카메라/방향 기반 AR입니다.

검증 2026-10-10:
- PC 송신 탭과 공개 HTTPS 수신 탭 WebRTC connected 및 실제 영상 수신 확인.
- 수신 탭의 200개 변경과 일시정지를 PC에서 확인, PC 상태의 수신 탭 반영 확인.
- 두 탭은 같은 PC의 Chrome을 사용한 통합검증입니다. 실제 휴대폰/LAN 교차 기기 검증은 아직 하지 않았습니다.
- PC에서 Microsoft Basic Render Driver가 확인됨. RTX 렌더링 검증 아님.
- 배경 탭 테스트 중 약 1 FPS 관측. 표시되는 조작 왕복(ms)은 영상 전체 지연이 아닙니다.
- 실제 폰의 카메라 합성/회전 센서 동작은 미검증.

이 연결은 서버가 켜져 있어야 동작합니다. 휴대폰 홈 화면에 설치해도 동일합니다.
재시작 시 접속 주소/연결 키가 바뀌므로 새 QR을 사용하세요.
연결 키는 앱의 해당 사이트 저장소에 보관하며, 서버가 다시 시작하면 무효입니다.

전송 화질 개선 v2 (2026-10-10)
- 지형 복잡도(렌더링 품질)와 영상 전송 화질을 분리했습니다.
- 전송 긴 변: 960 / 1280 / 1920 / 2560 픽셀. 화면 비율에 따라 짧은 변이 달라집니다.
- 전송 상한: 6 / 10 / 18 / 28 Mbps, FPS 상한: 30 / 24 / 24 / 20.
- 상한은 실제 보장 전송량이 아닙니다. 네트워크 혼잡 제어는 계속 작동합니다.
- SDP 응답 적용 후 인코더 파라미터를 설정하며 실패를 화면에 표시합니다.
- detail 힌트 및 maintain-resolution으로 해상도 우선 정책을 요청합니다.
- 실측 송신 Mbps, 해상도, 프레임당 인코딩 시간, CPU/대역폭 제한, 인코더를 표시합니다.
- 영상 연결 중 시그널링 타임아웃은 영상 단절과 구분합니다.
- 소프트웨어 렌더링 상태에서 장면 '최고'는 느릴 수 있습니다. 처음에는 장면 '균형', 전송 '선명 1920'을 사용하세요.
- Chrome이 Microsoft Basic Render Driver를 표시하면 RTX 그래픽 사용이 아닙니다. GPU 사용 여부를 먼저 해결해야 합니다.
- 근거: https://developer.mozilla.org/en-US/docs/Web/API/RTCRtpSender/setParameters
