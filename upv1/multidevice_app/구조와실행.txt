하늘마루: ClikaRT와 여러 기기로 확장하기 위한 코드
================================================

목표와 현재 범위
---------------
S22 후면 1배 카메라, NU40 DK + NU-IMU-LSM6DS3TR를 입력으로 유지한다.
인식 엔진을 교체해도 입력, 방향 판정, 추적, 출력 부분을 유지하도록 한다.
Windows 호스트 실행 코드와 Android에 넣을 계약/처리 코드를 준비했다.
현재 Android 앱/APK나 두 기기의 ClikaRT 실행 실적은 아니다.
ClikaRT SDK, 라이선스, 학습된 모델은 포함되지 않았다.
기존 합성 화면에 이 파이프라인을 연결하지 않았다.

파일 역할
---------
contracts.py : FrameSource / ImuSource / Engine / Tracker 인터페이스, 프레임·탐지 형식
inputs.py    : S22 영상 스트림 또는 녹화 영상의 OpenCV 호스트 어댑터
nu40_transport.py : 기존 NU40 USB·BLE 통신. USB 우선, BLE 구독 유지
imu.py       : 학습 JSON의 정규화 방향 벡터로 상/하/좌/우 판정
engines.py   : disabled / ultralytics / clikart 인식 어댑터
tracking.py  : 인식 엔진과 독립된 ByteTrack / BoT-SORT 어댑터
pipeline.py  : 인식 → 추적 → 방향 정보 포함 결과 생성
run.py       : Windows/Linux 진입점. --show를 지정할 때만 외부 영상 창 표시
config.json  : 카메라·IMU·인식·추적 설정. 경로는 이 설정 파일 폴더 기준
android/HaneulmaruCore.kt : Android용 입력·엔진·추적 계약, BLE 바이너리 해석,
                          USB/BLE 선택, 방향 판정, 처리 루프
assets/nu40-imu-direction-training.json : 기존 학습 JSON 사본

Windows 실행 준비
-----------------
Python 3.10 이상 설치 후 이 폴더에서 PowerShell을 연다.

  py -3 -m venv .venv
  .venv\Scripts\python.exe -m pip install -r requirements.txt

S22 영상 스트림 주소가 있는 경우:

  .venv\Scripts\python.exe run.py --source "S22 영상 주소" --show

S22 녹화 영상인 경우:

  .venv\Scripts\python.exe run.py --source "C:\videos\s22.mp4" --recording --show

실행.cmd는 영상 입력 주소를 직접 입력받는다. 브라우저 탭은 자동으로 열지 않는다.
실시간 카메라 연결에는 주소를 제공하는 S22 송신 프로그램이 필요하다.
이 묶음에는 S22 카메라 송신 앱이 포함되지 않았다. 기존 렌더링 수신 페이지를
S22 카메라 송신기로 취급하면 안 된다. 추후 CameraX 입력 어댑터를 연결한다.
장치 번호를 쓸 때도 S22가 실제 영상 장치로 연결된 번호를 지정해야 한다.

기본 engine=disabled는 실제 영상·IMU만 표시하고 탐지 결과는 빈 배열이다.
출력 engine.ready=false, engine.executed=false, reason으로 미연결을 표시한다.
이를 '물체 없음'이나 'ClikaRT 실행 성공'으로 해석하지 않는다.
기본 NU40 USB 식별자는 기존 펌웨어 VID/PID를 따른다. 필요하면
--imu-port COM5처럼 실제 포트를 직접 지정한다. 다른 프로그램이 해당 USB를
사용하고 있다면 종료 후 실행한다. BLE 이름은 기존 펌웨어의 NU40-IMU이다.
폰이 BLE를 사용하는 구성에서는 호스트도 동시에 직접 연결할 수 있다고
가정하지 말고, S22에서 호스트로 센서를 전달하는 ImuSource를 추가한다.

일반 YOLO 연결
--------------
  .venv\Scripts\python.exe -m pip install -r requirements-inference.txt
  .venv\Scripts\python.exe run.py --source "S22 영상 주소" --engine ultralytics --model "models/best.pt" --tracker bytetrack --show

기존 photo_color_v1 학습 코드의 R/B/G 3클래스 best.pt를 사용한다.
--tracker botsort로 BoT-SORT를 선택할 수 있다. 별도 ReID 모델을 자동으로
다운로드하지 않도록 이 어댑터에서는 ReID를 끈다.
낮은 신뢰도 관측도 추적기에 전달하고 표시 색상은 color_confidence 아래에서
UNKNOWN으로 바꾼다. 아직 추적 ID를 받지 않은 관측은 id=null이다.
추적기 버전은 기존 전달 코드와 같은 ultralytics==8.4.63으로 고정했다.

나중에 ClikaRT 연결
------------------
1. Windows Python용 SDK와 실행 라이선스를 발급받는다.
   requirements는 SDK를 자동으로 받거나 설치하지 않는다.
2. 받은 SDK README에 따라 같은 릴리스의 공식 wheel을 설치한다.
3. 라이선스 파일은 소스 밖에 보관한다. PowerShell 예시:

     $env:CLIKA_RT_LICENSE = "C:\private\clikart.license"

4. 학습된 YOLO11을 ONNX로 내보낸다.
   batch=1, imgsz=640, dynamic=False, half=False, nms=False.
   클래스는 0=R, 1=B, 2=G. 입력 images=[1,3,640,640] FP32.
   출력 output0=[1,7,N]: cx,cy,w,h,R확률,B확률,G확률.
   실제 입출력 이름과 모양을 확인하고 다른 형식은 디코더를 별도로 만든다.
5. 실행 예시:

     .venv\Scripts\python.exe run.py --source "S22 영상 주소" --engine clikart --model "models/best.onnx" --tracker bytetrack --show

ClikaRTEngine은 공식 Python ONNX 진입점에 맞춰 작성했다.
모델은 한 번 로드하고 프레임마다 letterbox → RGB/FP32/NCHW →
ClikaRT 추론 → 원본 박스 복원 → NMS → 공통 추적기를 거친다.
SDK/라이선스/모델 오류 시 다른 엔진으로 조용히 대체하지 않고 중단한다.
이 PC에는 SDK가 없어 실제 ClikaRT 실행을 수행하지 않았다.
발급된 SDK API, 지원 연산, 모델 출력 계약 확인은 남아 있다.
기본 CPU이며 GPU 선택은 받은 SDK와 실제 드라이버에 맞춰 설정한다.

Android 확장
------------
HaneulmaruCore.kt는 Android 프로젝트에 넣을 라이브러리 소스이다.
화면, CameraX 수명주기, BLE 권한/검색/연결, Gradle 프로젝트는 포함하지 않았다.
SDK 없이 가상의 io.clika 클래스를 만들거나 실행을 흉내 내지 않았다.

추후 Android 앱에서 다음 순서로 연결한다.
1. CameraX 영상을 회전·미러 해제한 RGB로 바꾸고 CameraFrame을 만든다.
2. BLE 17바이트 알림을 Nu40Decoder.binary로 읽는다.
   USB/legacy NDJSON이 필요하면 플랫폼 어댑터를 추가한다.
3. 같은 학습 JSON의 directions/rate_threshold_dps/similarity_threshold로
   DirectionClassifier를 만든다.
4. 공식 Android AAR·라이선스를 초기화하는 실제 SDK 구현을
   ClikaRtBinding에 넣고 ClikaRtEngine으로 연결한다.
5. ByteTrack의 Android 구현을 TrackingEngine에 연결한다.
   현재 NoTracking에는 ID 추적 기능이 없다.
6. 작업 스레드에서 Pipeline.process를 호출하고 최신 결과만 표시한다.
   처리 중 들어온 프레임에는 null을 반환한다. 프레임을 계속 쌓지 않는다.

Windows와 Android는 같은 클래스·박스·결과 계약을 사용한다.
이는 확장 기반이며 '두 기기의 같은 앱에서 ClikaRT 추론 완료'를 입증하지 않는다.

시각·좌표 계약
--------------
영상은 회전 보정된 원본 픽셀 좌표이고 xyxy는 그 영상 내부의 좌표다.
Windows의 시각은 OpenCV decode 시점의 host monotonic ms이다.
USB/BLE t_ms는 보드의 별도 32bit 시계라 카메라 시각과 직접 비교하지 않는다.
IMU는 추론 전에 얻은 최신 패킷을 쓰고 350ms 이상 오래되면 무효이다.
imu_alignment=host_arrival_approximate이며 촬영 노출 시각의 정밀 동기화가 아니다.
녹화 영상에는 현재 실시간 IMU를 붙이지 않는다.
Android에서는 카메라 시각/센서 수신 시각을 같은 단조 시계로 맞춘다.
정밀 동기화에는 별도 시계 동기화와 지연 측정이 필요하다.
이 코드는 IMU로 실제 카메라 자세나 절대 좌표를 보정하지 않는다.
거리 계산은 후속 작업으로 남겨 range_m=null이다.
S22 FOV 85도는 축 기준 미확정 메타데이터로 투영에 사용하지 않는다.

다른 코드에서 가져다 쓰기
-----------------------
  from multidevice_app.pipeline import Pipeline
  from multidevice_app.contracts import Frame

엔진·추적기·방향 판정기를 Pipeline에 주입하고 Frame과 imu_state를 전달한다.
process()가 결과 dict를 반환한다. 화면·파일·전송 코드는 이를 받아 사용한다.
JSONL은 --jsonl로 명시할 때만 새 파일에 저장하고 기존 파일을 덮어쓰지 않는다.
IMU가 끊겨도 영상 처리는 계속되고 방향은 unavailable로 표시한다.
외부 실행 창에는 x/y/z·각도 대신 UP/DOWN/LEFT/RIGHT만 표시한다.

wan_V1 정리본의 실행 최적화
-------------------------
외부 화면만 표시할 때는 사용하지 않는 JSON 변환을 건너뛴다.
JSONL 파일은 스트림으로 쓰고 프레임 처리 중 기본 0.5초 간격으로 flush한다.
정상 종료 시 파일을 닫으며 남은 버퍼를 저장한다. 강제 종료나 전원 중단
직전의 버퍼는 저장되지 않을 수 있다. 매 프레임 즉시 저장이 필요하면
--flush-every-frame을 사용한다. 표준 출력은 기존처럼 즉시 flush한다.
ClikaRT 전처리 영상/FP32 텐서 버퍼는 재사용하고 박스 복원은 배열 연산을
사용한다. 엔진은 기존 Pipeline처럼 한 스레드에서 순서대로 호출한다.
NU40 USB/BLE 구현과 학습 모델을 기존 화면과 함께 공유한다.
이번 변경에서는 실행 테스트나 속도 측정을 수행하지 않았다.
