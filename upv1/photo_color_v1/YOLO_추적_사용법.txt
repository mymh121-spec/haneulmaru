경량 정리본: 학습 데이터 변환 전 python restore_training_data.py로 사진·라벨을 복원하세요. 이미 학습된 best.pt로 영상을 추적할 때는 복원할 필요가 없습니다.

하늘마루 · YOLO11 + ByteTrack / BoT-SORT

구성
  prepare_yolo_rgb.py : 기존 정지사진을 YOLO R/B/G 드론 탐지용으로 변환
  train_yolo_rgb.py   : GPU PC에서 YOLO11n 전이학습
  track_yolo_rgb.py   : 학습한 best.pt로 영상/카메라 탐지와 추적
  drone_coordinates.py : 드론 박스 중심 + 자세를 ENU 방향으로 변환
  coordinate_imu.py : 기존 NU40 서버에서 각속도를 읽는 별도 자세 입력
  drone_coordinate_config.json : 북쪽 기준 및 임시 카메라 투영 설정
  requirements-yolo.txt : Python 의존성

현재 제공 상태
  코드만 준비한 상태이며 학습, 모델 추론, 추적 시험은 실행하지 않았습니다.
  best.pt는 아직 없습니다. 다른 GPU PC에서 아래 학습을 완료해야 생깁니다.
  NU40 서버를 지정하면 자세 입력과 연결할 수 있습니다. 폰 카메라 자동 탐지는 학습 모델 및 영상 연결이 필요합니다.

탐지 대상
  id 0=R / id 1=B / id 2=G.
  박스는 작은 색상 표식이 아니라 '그 색의 표식을 가진 드론 전체'입니다.
  원본(none) 300장 제외, 합성 표식 사진 900장 사용:
  train 630 / val 180 / test 90. 기존 원본 단위 분할을 유지합니다.
  추론할 때는 manifest나 정답 좌표를 읽지 않고 YOLO가 드론 박스와 색상을 예측합니다.

GPU PC 설치 (Python 3.10 이상, 3.11 권장)
  폴더 전체를 GPU PC로 복사한 뒤 photo_color_v1에서 작업합니다.
  python -m venv .venv-yolo
  Windows: .venv-yolo\Scripts\activate
  Linux:   source .venv-yolo/bin/activate

  먼저 https://pytorch.org/get-started/locally/ 에서 해당 GPU/OS에 맞는
  CUDA 지원 PyTorch 설치 명령을 선택해 실행하세요.
  python -m pip install -r requirements-yolo.txt
  python -c "import torch; print(torch.cuda.is_available())"
  True가 나와야 --device 0으로 학습할 수 있습니다.

1. 데이터 변환 (새 폴더 yolo_rgb 생성, 기존 데이터 유지)
  python prepare_yolo_rgb.py
  다른 위치를 원하면 --output 새폴더 를 지정합니다.
  같은 이름의 출력 폴더가 있으면 덮어쓰지 않습니다.

2. GPU 학습
  python train_yolo_rgb.py --device 0 --epochs 80 --batch 8
  GPU 메모리가 부족하면 --batch 4 또는 --batch 2로 줄입니다.
  기본 모델: yolo11n.pt (첫 실행 시 공식 사전학습 가중치 다운로드).
  기본 입력 크기: 640. 색조·채도·RGB 채널 바꾸기 증강은 비활성화했습니다.
  결과: runs_rgb/drone_rgb/weights/best.pt
  반복 실행 시 drone_rgb2 등 새 폴더가 만들어지므로 마지막 출력 경로를 확인하세요.
  중단된 학습 이어가기:
  python train_yolo_rgb.py --device 0 --resume runs_rgb/drone_rgb/weights/last.pt
  이어갈 때는 원래 학습 환경과 데이터 경로를 유지하세요.

3. 영상 추적: 둘 중 하나를 선택합니다 (동시에 두 추적기를 적용하지 않음)
  ByteTrack:
  python track_yolo_rgb.py --weights runs_rgb/drone_rgb/weights/best.pt --source input.mp4 --tracker bytetrack --device 0 --show

  BoT-SORT:
  python track_yolo_rgb.py --weights runs_rgb/drone_rgb/weights/best.pt --source input.mp4 --tracker botsort --device 0 --show

S22 카메라 기준 정보
  camera_calibration_s22/reference_info.json 에 현재 확인된 정보만 기록되어 있습니다.
  카메라: Samsung Galaxy S22 (SM-S901N), 후면 1배율
  카메라와 자 사이 거리: 30cm
  자의 전체 길이: 31cm, 눈금 구간: 0–30cm
  기준 사진: camera_calibration_s22/reference_images/
  이 정보는 추적기에서 사용하지 않으며, 카메라 보정값이나 물체까지 거리·실물 크기를 계산하지 않습니다.
  이후 사용 목적과 촬영 정보가 정해지면 그에 맞게 관련 코드를 추가합니다.

촬영 시작 방향 = 북쪽 · 시스템 좌표 기록
  기본 출력의 system_coordinates에 ENU 방향 벡터와 방위·고도각을 추가합니다.
  기본 수직 화각 55°는 기존 렌더러의 임시 모델이며 S22 측정값이 아닙니다.
  실제 드론 거리와 공간 위치는 null입니다. 자세 입력이 없으면 고정 카메라라고 가정합니다.
  창 없이 기록: --jsonl drone_coordinates.jsonl (--show를 생략)
  NU40 연동: --imu-host-url "실행창의 PC주소 (#연결키 포함)"
  다른 코드의 자세: --pose-json pose.json
  자세한 실행법과 로직: SYSTEM_COORDINATES.md

  카메라는 --source 0 을 사용합니다. 화면은 --show를 넣었을 때만 외부 창으로 열립니다.
  Q 또는 Ctrl+C로 종료합니다. CPU에서 실행할 때는 --device cpu를 지정하세요.
  영상 저장: --save-video tracked.mp4
  연동용 결과 저장: --jsonl tracks.jsonl
  기존 결과 파일은 덮어쓰지 않으므로 매번 새 이름을 사용하세요.
  출력 예시 형식: {"frame":1,"tracks":[{"id":1,"code":"R","raw_code":"R","confidence":0.91,"xyxy":[10,20,100,120]}]}
  위 예시는 형식 설명이며 실제 측정값이 아닙니다.
  id=null은 아직 추적 ID가 없는 탐지입니다. UNKNOWN은 색상 신뢰도가 낮거나 흔들리는 상태입니다.
  confidence는 현재 YOLO 탐지 신뢰도이며 보정된 확률이나 누적 색상 신뢰도가 아닙니다.

4. 다른 Python 프로그램에서 연동
  from track_yolo_rgb import RGBTracker
  tracker = RGBTracker("best.pt", tracker="botsort", device="0")
  tracks = tracker.update(frame)  # frame: OpenCV의 BGR 이미지
  # tracks 안의 id, code, xyxy를 UI/통신 코드에 전달
  tracker 객체는 연속 프레임마다 재사용해야 ID가 유지됩니다.
  다른 영상으로 바꾸면 새 RGBTracker 객체를 만드세요.

선택 기준과 한계
  ByteTrack: 우선 비교할 가벼운 기준 추적기.
  BoT-SORT: 움직이는 카메라에 대한 보정 포함. 기본 ReID는 꺼져 있습니다.
  최근 최대 7프레임의 색상 결과를 가중 투표하지만 ID 교환을 완전히 막지는 못합니다.
  표식이 작거나 가려지면 색상을 혼동할 수 있습니다. none은 학습에서 제외했으므로
  표식 없는 드론을 자동으로 NONE으로 분류하도록 학습된 모델은 아닙니다.
  이 자료는 정지사진뿐이라 탐지 학습은 가능하지만 추적 성능(IDF1/HOTA 등)을 측정할
  영상·프레임별 ID 정답이 없습니다. ByteTrack/BoT-SORT 자체를 이 사진으로 학습하지 않습니다.
  실제 연속 영상, 표식 없는 드론, 드론 없는 배경을 별도로 수집해 평가해야 합니다.
  합성 원형 표식으로 학습한 성능이 실제 스티커·멀리 있는 드론에서도 같다고 보장할 수 없습니다.

## 카메라 사양 추가 정보

알려주신 카메라 정보는 화각 약 85°(가로·세로·대각선 기준 미확인), 조리개 f/1.8입니다. 화각 기준을 확인하기 전까지 85°는 방향 계산에 적용하지 않고 기존 임시 수직 화각 55°를 유지합니다. 조리개는 기록용이며 방향 벡터 계산에는 사용하지 않습니다.
