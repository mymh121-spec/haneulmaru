[2026-10-10 NU40 연동 추가]
현재 연결된 NU40 DK + NU-IMU-LSM6DS3TR는 USB v1 NDJSON / BLE 17바이트 패킷을 사용합니다.
실제 구현과 현재 사용법은 NU40_연동_사용법.txt를 먼저 확인하세요.
아래는 원본 전달 당시 참고 자료이며, andrew.ino 패킷은 현재 NU40 패킷과 다릅니다.

NUCODE 담당자에게 — 소프트웨어 입력 합의

목표: 우선 IMU로 가상 카메라의 회전 시점을 조작합니다.
현재 앱은 휴대폰 방향 센서를 사용합니다. NUCODE 포트는 아직 추가되지 않았습니다.
IMU 가속도를 위치로 단순 이중 적분해 정확한 공간 이동값이라고 취급하지 않습니다.
회전 입력과 위치 이동 입력은 분리해서 연결해야 합니다.

[현재 로컬 자료에서 확인한 원시 패킷]
참고 펌웨어: 해커톤/solve in toy/andrew/andrew.ino의 복사본.
시리얼 설정: 115200. 데이터는 JSON 객체 한 개 + 줄바꿈(JSON Lines).
실제 출력부의 키는 ts_ms와 imu.ax_g/ay_g/az_g/gx_dps/gy_dps/gz_dps입니다.
파일 상단의 CSV/time_ms/a/g 설명 일부는 실제 출력부와 다르므로 출력부 기준으로 읽으세요.
가속도: g (중력 포함), 자이로: deg/s. 수신 파서에서는 m/s² 및 rad/s로 변환.
calibration=ready면 원본 파서는 보드 자이로 보정을 이미 수행했다고 취급합니다.
샘플의 0,0,1g는 단위 예시이며 실제 보드 장착 축 방향을 의미하지 않습니다.
파서 참고본은 기존 코드 발췌로, 하늘마루 서버에 자동 연결되지 않습니다.
펌웨어는 하늘마루 전용 버전이 아닙니다. 팀원 현재 펌웨어를 덮어쓸 필요 없습니다.
참고본의 보드/센서 설정은 실제 팀원이 사용하는 버전과 별도로 대조해야 합니다.

[현재 하늘마루 입력]
experiments/haneulmaru_pro/app.js : streamBridge.control(d)
receiver.js : 휴대폰 DeviceOrientation → 상대 quaternion → DataChannel
형식 예: {"type":"control","seq":1,"q":[0,0,0,1]}
q 순서는 Three.js의 [x,y,z,w], 정규화된 quaternion입니다. 각도 4개가 아닙니다.
seq는 연결 세션 내 단조 증가 정수. 오래되거나 같은 seq는 무시됩니다.
q는 초기 지점 기준 상대 회전입니다. 현재 카메라 기준 자세에 곱해 적용됩니다.
현재 월드는 Y가 위인 Three.js 좌표계입니다. 센서 축 → 화면 축 변환이 필요합니다.
직접 IMU를 연결할 때 휴대폰 회전 입력과 동시에 보내지 않도록 입력원 선택을 추가해야 합니다.
seq도 기존 휴대폰 채널과 충돌하지 않도록 입력원별 처리 또는 하나의 어댑터에서 부여해야 합니다.

[팀원이 알려줄 내용]
1. 보드/센서 이름과 펌웨어 버전, 실제 출력 JSON 10줄
2. USB COM 또는 BLE 중 사용 방식. COM이면 포트와 baudrate.
3. 가속도/자이로 단위, timestamp 단위, 실제 샘플 주기
4. +X/+Y/+Z 축의 장착 방향과 회전 부호
5. 원시 값인지 자세 추정값인지. quaternion이면 xyzw/wxyz와 회전 순서/기준계
6. 영점 보정 수행 위치(보드/PC), 보정 완료 표시, 끊김/재연결 동작

[연결할 위치 — 아직 구현 전인 제안]
NUCODE → USB 수신 → 단위 변환/자세 계산 → 초기 자세 기준 회전 → PC 렌더러.
처음에는 한 축씩 +90° 회전과 초기 지점 복귀를 확인합니다.
그다음 세 축과 가로/세로 화면, 폰 센서와 NUCODE 입력원 전환을 확인합니다.
3D 렌더링 루프와 별도로 수신하고, 늦은 샘플이 쌓이지 않게 최신 자세를 적용합니다.
체감 지연은 센서 측정부터 화면 표시까지 따로 측정합니다. ping 왕복값과 다릅니다.
